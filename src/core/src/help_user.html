🚀 快速上手3 分钟出阵

  1. 懒人起步：左栏 📦 预设 → 世界预设（九套成品画像）一键载入已验证脚本（复兴/童话/西部/埃及/桑葚/海盗/龙芋/功夫/功夫纯火龙v2，含阵型/卡槽/顺序/路由/Boss/抛花），载入后微调即可导出。
  2. 在左侧植物库点选植物 → 点棋盘格子放置（也可直接拖）；拖到卡槽即配队（卡槽现在带植物头像，一眼可认）。
  3. 顶部工具栏点 🔢 顺序 →「生成草案」一键生成种植链（瓷砖格会自动在链尾铺瓷砖萝卜；金卡主力超 3 格时前 3 格按未覆盖行优先排序，O9 更容易过）；🔍 检查 看 O1~O9 体检（0 error 再往下走）。
  4. 点左栏 📤 导入导出 →「生成 pipeline 片段」拿走脚本，或先「导出 JSON v2」存底稿——完整上线步骤见导入导出全流程。

🌱 棋盘操作

  • 放置/擦除：点选画笔后点格子；右键清空格子/卡槽；右键植物名=从库中删除。
  • 互换：格子↔格子拖拽互换；拖列头=整列互换；拖行号=整行互换。
  • 复制画笔：空白画笔（点棋盘空白处取消选择）时点格子=复制该格组合，再点其他格连续粘贴。
  • 编辑：双击格子改主植物名（输入 - 清空）。
  • 尺寸：右下「列数/行数 + 应用尺寸」（1~9 列、1~5 行）。
  • 瓷砖：工具组「放置/移除瓷砖」，独立于植物、不参与复制；导入时用 [瓷] 标记。
  • 动作：分棋盘专用 抛花/抛蕾/喂豆/铲除/delay，点格子在原组合后追加（可叠加，例：大守卫菇+喂豆+delay500+铲除）。
  • 小关抛花：路由面板勾选「小关抛花」并填 花卡槽+抛花格（如 7-1,7-2）后，导出会在 deck1「点波_初始」后自动插入抛花步，task 自带「小关是否抛花」开关与每朵花行列坐标输入（西部同构，格号可到 MPZ 界面改）。
  • 特效开关：工具栏「特效」关闭后仅保留瓷砖/芦荟提示；分阵型开关显示 总阵型/前期/后期 三个棋盘（可「校验一致性」）。

🌿 叠种与融合

  • 藤蔓（毒藤/南瓜头/豆藤/小守卫菇）叠在主植物上，显示如 桑葚(毒藤)；一格最多一种藤蔓。
  • 融合（原豌/电豌/火豌/冰豌/毒豌）只叠在「大哥」上，棋盘显示 原大/电大/火大/冰大/毒大，导出仍为完整 大哥+材料。
  • 导入时自动识别组合写法：原大=大哥+原豌、原碗→原豌 纠错、-/空=空格。

🃏 卡槽与配队

  • 卡槽 1~8 = 配队1；点「配队2」展开卡槽 9~16（面板已带植物头像图）。
  • 槽位归属决定路由与检查：deck1 步只能用卡槽 1~8，deck2 步只能用 9~16（违例会被 O10 拦下，见常见坑）。

🔢 顺序链与🥇金卡推演O9 是出脚本前的必过项

  • 生成草案：按棋盘+卡槽一键生成种植链（融合对相邻、按槽分组、插缝结算自动插入）；拖拽可微调。
  • 画笔追加：顺序面板打开时，用植物画笔点格子=追加种植步（同格去重）。
  • 手动加步：加步栏「+种植」可临时插入任意卡槽/格子的种植步（调试用，不必在棋盘上）；所有加步自动插到链尾点波之前——追加到点波之后是孤儿步、永不执行。位置用拖拽或 ↑↓ 调整，行内可改格子/卡槽/pre/post。
  • 检：该步挂 ColorMatch 金卡检测（失败走回退），一般从第 2 个融合格开始挂。
  • 校验规则：O1覆盖 O2融合次序 O3时序 O4检测位 O5插缝 O6 deck2专属点波 O7捡花 O8节奏 O9金卡3次+行覆盖 O10卡槽归属。

🥇 金卡推演（O9）

金卡（橙色品质）初始每种只有 3 次。推演只按前 3 次计算（第 4 次起失效），检查第一关开始时每一行是否至少有一个守阵主力：大哥(含x大)/洋芋/桑葚/药师/暗物质火龙果（单行）等算主力；气流、珊瑚等辅助不算；军炮/迫击炮类所在行直接视为安全。

判读：「超初始 3 次」标记是 info 不是错误——同种第 4 次以后的种植是给后续关卡/铲补留的通用位，第一关不生效属预期；只有「融合格超次大哥缺检」和「行无守阵主力」才是必须修的 error。

🔗 链路可视化（与棋盘结合）

  • 顺序面板打开时棋盘叠加步数徽章：金=金卡步 · 绿=追踪安全 · 红=超3次失效；行号 绿✓有主力 / 黄⚠仅追踪 / 红✗无主力。
  • 顺序列表悬停任一步，棋盘对应格高亮；「棋盘链路可视化」勾选框可关。

🧭 配队路由与计数模拟

  • 模式：尾数分流（复兴/童话/龙芋）/ 阶段分流（海盗）/ 无计数（埃及/西部单卡组）。
  • deck2尾数、Boss尾数、front10/30、喂豆格等参数均有「已验证预设」一键填充；「规则自检」跑测试向量。
  • N关起补白萝卜 (bailuo_from)：第 N 关起普关进入「重种白萝卜」循环（agent 改写点波路由，火龙v2=60，防后期吸阵破阵）；白萝卜落格/槽位自动取自 deck1 顺序里的白萝卜步，留空=关闭。
  • 关内点波默认档 (wave_mode)：非空时导出的 task 会带「关内点波」三档选项（不点波=只等结算最稳 / 默认=交替 / 狂点=突发连点），所选档为默认；留空=不生成该选项，维持旧行为。
  • 「模拟」按关卡序列逐关判定分流，可视化计数条与单关判定链；≥bailuo_from 的普关会标注「走补白萝卜循环」。

👑 Boss 关链编辑

  • 范式：叠电大=叠×2轮→(能量花)→加速→循环喂豆（复兴/西部）；喂豆开大=喂豆→加速→喂豆→循环（童话，末步勾循环）。
  • 识别boss关→神器补给骨架由导出自动补齐；可生成喂豆位置 select（45格）；B1~B7 一键校验（B7 会拦「Boss 关用 deck2 卡槽」的叠种）。

📥📤 导入导出全流程重点章 · 从画布到能跑的脚本

5.1 先分清三种文件（混用必失败）

文件长什么样干什么用正确入口
v2 阵型 JSON（源底稿）纯 JSON，开头 {"version":2,"meta":…，含 boards/slots/order/route/boss阵型的完整存档，改阵型全靠它回灌应用粘贴的 JSON v2
存档槽位整包JSON，若干具名槽位（棋盘+卡槽+顺序+路由+Boss 整包）多套阵型打包带走/换机存档面板 粘贴→导入全部
pipeline 片段大文本：体检注释 + pipeline 节点 JSON + task 片段 三段拼在一起部署用成品（给 MPZ 的最终形态）拆开后部署（见 5.3/5.4）；不能整份直接导入
⚠ 最常见错误：把 pipeline 片段粘进「应用粘贴的 JSON v2」（它不是 version:2 格式），或把存档整包当 v2 JSON 导入——都会报错。先看文件开头长什么样，再选入口。

5.2 导入：四种途径

A. 手里有 v2 阵型 JSON（最常用，工具自己的源格式）：

  1. 左栏 📤 导入导出，把 JSON 整段粘进大文本框。
  2. 点 应用粘贴的 JSON v2 ——棋盘/卡槽/顺序/路由/Boss 全部还原（可撤销）。

B. 手里是存档槽位整包：

  1. 左栏 💾 存档 面板，整包粘进 IO 框。
  2. 点 导入全部 → 列表出现各槽位 → 点要用的槽「载入」到画布。

C. 手里是已部署的 MPZ pipeline（YS_*.json / Endless_*.json 纯 JSON 文件，可多选合并）：

  1. 导入导出面板下半区 选 pipeline JSON（可多选）。
  2. 点 解析（先看报告） ——走链规则还原出 步数/植物名/路由/警告，先读报告。
  3. 没问题再点 应用到画布（可撤销）。

D. v4 桌面版：Agent 改完的输出——Agent 工作台里点 📥 应用到布阵，自动从回复中提取 v2 JSON/片段应用（优先取最新一轮完整文档）。

5.3 导出：从画布到能跑的 MPZ 脚本（照抄 7 步）

  1. 配齐五件套：棋盘 + 卡槽（配队2要开）+ 顺序链（deck1/deck2）+ 路由 + Boss 链。跑 🔍 检查 与 🥇 金卡推演，O/B 全部 0 error（O9 的「超次」info 不拦）。
  2. 存源底稿：点 导出 JSON v2 → 下载 .json（桌面版弹原生另存为）。这步必做：以后改阵型、换机、Agent 修改，全靠这份 v2 源回灌。
  3. 定前缀和任务名：面板顶部「节点前缀」填本套脚本独用的前缀（如 fx_、ty_——与 MPZ 里已部署的脚本不重名）；「任务名」可自定义（写进 interface.json 的任务名，留空自动「世界无尽(v2生成)」，会记忆）。
  4. 生成片段：点 生成 pipeline 片段。得到三段式文本，分界标记直接写在文本里：①头注释（体检结论，error 必须清零再部署）→ 见「↓↓② pipeline 节点 JSON」标记即为第②段起点 → 见「↓↓③ task 片段」标记即为第③段（option+task）起点。用 复制 或 下载 .json 取走；不拆也没关系——下一步可以一键部署。
  5. 一键部署（推荐）：点 🚀 部署到 MPZ，工具自动做齐：体检 error 门（未清零会拦下并列清单）→ 实时生成并写入 resource_self/pipeline/Endless/YS_前缀.json 与 resource_self/task/前缀_wj.json → interface.json 注册（resource「自制无尽」+ import 片段 + task 条目，幂等不重复）→ agent 计数器检查修补（main.py 自动补 import；fx_counter.py 缺失时用内置源码直接写入，换电脑也能自愈）。所有被覆盖文件先备份为 *.bak.时间戳；逐步报告显示在导出框。前提：v4 桌面版 + 「🌐 服务」面板里 MPZ 根目录正确（校验前置：根不对时一个文件都不会写，并提示去服务面板重设）。
  6. 重启 MPZ（MFAAvalonia）重载资源；任务列表资源切到「自制无尽」才能看到自制无尽任务。
  7. 首跑清单：「初始化卡槽和草坪位置」=是；「启动时关卡数」填当前关（中途加入必填）；开「监控窗口」看实时关卡数；有检步的留意首跑识别（见 5.5 坑位）。

5.4 部署细节与还原

  • 内置一键是幂等的：同一画布反复点不会重复注册；官方 interface.json 大更新后，打开各阵型画布逐个点一次「🚀 部署到 MPZ」即可全部还原（agent/main.py 的计数器 import 也会自动补回）。
  • 手动拆装（学原理/离线机器）：②段存成 resource_self/pipeline/Endless/YS_名字.json；③段的 option 合并进 resource_self/task/前缀_wj.json；interface.json 三处——resource[] 加「自制无尽」{path:[./resource, ./resource_self]}、import[] 加片段路径、task[] 加条目（name/entry/option/resource=["自制无尽"]）。改完必须仍是严格 JSON（无注释/尾逗号）。
  • 简介不用手写：③ task 片段的 description 已按现网「卡槽 配队1[…] 配队2[…]｜注意…」格式生成（卡槽表+路由/Boss/抛花摘要），注册 task[] 时原样抄进 description 即可，与任务列表文案天然对齐；JSON v2 源里也存了一份（meta.intro）。
  • 部署后校验：🔍 检查 面板选刚部署的文件，S1 断链应=0；任务列表资源切「自制无尽」应能看到任务。
  • 回滚：所有被覆盖文件都有同目录 *.bak.时间戳 副本，改回文件名即回滚。

5.5 常见坑（都踩过）

⚠ 三种格式混用：见 5.1 表——按文件开头特征选入口。
⚠ 片段不是纯 JSON：三段拼在一起的片段不能整份喂给「MPZ pipeline 导入」或直接部署（解析失败）。要回改画布请用 v2 源走 A 途径；要部署就按 5.3 第 5 步拆开。
⚠ 前缀冲突：同一 MPZ 内每套脚本前缀必须独立（fx_/th_/ty_…），撞名节点会互相覆盖。
⚠ 卡槽归属：deck1 步引用卡槽 9~16（或 deck2 用 1~8）= 进关后摸到的是另一配队的卡、静默种错（O10 拦截）。
⚠ 检位实测：「检」的金卡检测条坐标按官方槽位探针推算，卡槽3 是实测校准值，其他槽位（O10b 会提示）首次上机先实测一次。
⚠ agent 共用：计数器 agent 是所有自制无尽共用的，双任务不要同时跑。

❓ 常见问题

  • 金卡3次是什么？无尽开局金卡（橙色植物）每种只有 3 次种植次数，超出种不下；O9 据此检查开局布阵是否成立。
  • 为什么「原大」提示橙色而「原豌」是蓝色？叠在大哥上的融合体是金卡本体；材料品质只影响材料种植次数。
  • 数据存在哪？浏览器 localStorage（v2/v3 通用键）；重要阵型用存档导出或 v2 JSON 带走。
  • 桌面版和浏览器版差异？桌面版多 Agent 工作台、原生另存为、原生 MPZ 直读、完成通知；棋盘功能完全同源。
  • 导出后点「下载 .json」弹打开？已修复为另存为（2026-09-06），如遇旧版请更新桌面壳。
